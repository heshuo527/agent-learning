# DSH 源码导览

把 DeepSeek Harness 里和你学习大纲对应的 7 处关键代码提取出来,做成「朴素版 vs 生产版」对照讲解。

## 打开方式

**双击 `index.html` 就行。** 零依赖、零构建,不需要装任何东西,也不需要起服务器。

读源码看不懂,通常不是因为代码难,是因为**没有对照物**。这个站点的每一节都摆两段代码:

- **朴素版** —— 你在第 1 周会自己写出来的实现,二十行以内
- **生产版** —— 同一个功能在真实 harness 里的样子

然后按「朴素版漏了什么」来讲,不是逐行解释语法。

## 阅读顺序

侧栏按四个阶段分组,每节标了「建议时机」—— 不用自己判断从哪开始。

| 顺序 | 阶段 | 标题 | 对照知识点 | 对应包 |
|---|---|---|---|---|
| 起 | 第一步:打底 | 预备知识:读代码前先懂这些 | — | — |
| 1 | 先看这两节 | 循环与终止条件 | ③ | `dsh-agent-loop` |
| 2 | 先看这两节 | 参数解析:把崩溃变成可恢复 | 坑 4 | `dsh-agent-loop` |
| 3 | 把循环补完整 | 工具怎么定义:真实写法长什么样 | ② | `dsh-tool-fs` |
| 4 | 把循环补完整 | 一轮要调多个工具,能不能一起跑 | 副作用分级 | `dsh-tools` + `dsh-agent-loop` |
| 5 | 让它可靠、不烧钱 | 它卡在重复调用里怎么办 | ⑥ | `dsh-repeat-tool-reminder` |
| 6 | 让它可靠、不烧钱 | 上下文太长了怎么办 | ④ | `dsh-compaction-tool-result-pruner` |
| 7 | 让它可靠、不烧钱 | 钱花在哪了:看懂 token 账单 | ⑦ | `dsh-token-meter` |

**预备知识那一页是给完全的小白准备的**:讲清一次 API 调用里有哪些角色、五个必须理解的概念、一张术语速查表,最后是「值得记住的四条」。

这里刻意只把四条标成「值得背」—— agent 这块需要死记的东西极少,大部分是理解。术语表是查的,不是背的。

「对照知识点」指的是 `AGENT-LEARNING.md` 第 2 节的七个知识点编号,方便两边对着看。

读完一页可以点底部的「标记为读完」,侧栏会打勾并显示进度(存在浏览器 localStorage,换设备不同步)。

## 建议怎么用

**不要现在全看完。** 侧栏分了三个阶段,每个阶段对应你学习路线上的一个时间点:

- 写完 Day 3(循环)→ 看第 1、2 节
- 写完 Day 4(多工具)→ 看第 3、4 节
- 第 2 周做工程化 → 看第 5、6、7 节

现在直接看后面几节会有点飘,因为还没被坑过。

## 文件结构

```
dsh-source-tour/
├── index.html    外壳
├── styles.css    样式
├── data.js       ★ 全部内容:basics(预备知识)+ stages(阅读顺序)+ topics(7 节代码与讲解)
└── app.js        渲染:路由 / 语法高亮 / 已读状态 / 翻页
```

**要改内容,基本只改 `data.js`。**

### 改预备知识页

`data.js` 里的 `basics.blocks` 是一个区块数组,`app.js` 按 `type` 渲染。支持六种:

```js
{ type: "h",       text: "小节标题" }
{ type: "p",       text: "段落,支持 **粗体** 和 `行内代码`" }
{ type: "code",    code: "代码(模板字符串)" }
{ type: "callout", text: "高亮提示块" }
{ type: "list",    ordered: true, items: ["条目一", "条目二"] }
{ type: "table",   head: ["列一", "列二"], rows: [["a", "b"]] }
```

### 加一节新内容

两步:

1. **往 `topics` 数组追加一个对象**(字段照抄现有的):

```js
{
  id: "唯一英文 id(会变成 URL 的 #hash)",
  num: "对照学习文档的哪一节",
  title: "标题(侧栏不用它,以 stages 里的为准)",
  pkg: "包名",
  file: "文件路径",
  idea: "这一节解决什么问题",
  naiveLabel: "朴素版是哪个阶段写的",
  naive: "代码(模板字符串)",
  prodLabel: "生产版标题",
  prod: "代码(模板字符串)",
  notes: [{ h: "小标题", p: "讲解" }],
  takeaway: "一句话结论"
}
```

2. **在 `stages` 里把它排进阅读顺序** —— `stages` 是「怎么读」,`topics` 是「内容」,
   两者分开是为了让阅读顺序在一个地方一眼看全,方便调。

```js
items: [
  { id: "新章节的 id", title: "侧栏显示的标题", sub: "侧栏的一行说明", when: "建议时机" },
]
```

没排进 `stages` 的章节不会消失,会自动落到侧栏最后的「未分组」里。

注意:代码里的反引号和 `${` 在模板字符串中要转义成 `\`` 和 `\${`。
